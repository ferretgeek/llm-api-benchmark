# LLM API benchmark

[中文](README.md) · English

Measure how long an LLM API takes to start replying, how fast it produces output, and its cache usage and estimated cost, so you can compare endpoints under the same conditions.

**Requirements:** Python 3.10+ and your own endpoint URL, API key, and model name. Real benchmarks need internet access and may incur charges; the online demo uses simulated data.

[View the demo](https://ferretgeek.github.io/llm-api-benchmark/) · [Run locally](#run-locally) · [Measurement method](docs/测量方法.md)

Requests run one at a time in fixed scenarios, with first-token latency, output speed, and usage reported separately. Warm-ups count toward cost but not the formal speed results.

## What you get

- **Three locked single-stream scenarios** — uncached limit, daily conversation, and high-cache Codex. **Concurrent throughput is never presented as single-request speed.**
- **Visible process** — a live dashboard, quality gates, per-request details, history comparability checks, and one-time JSON reports.
- **Clean accounting** — complete usage and interrupted estimates stay separate, and **warm-ups count toward usage but never enter the formal speed distribution.**
- **Four themes** — Iris, Jade, and Sunrise light palettes plus a global dark theme whose background is exactly `#17191d`.
- **Runs anywhere** — Windows launchers, local Python, Docker Compose, and Linux systemd + SSH tunnel.

## Run locally

Requires Python 3.10 or newer.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python token_stress_test.py
```

On Windows you can also double-click `一键启动.bat` after installing dependencies. `一键结束服务.bat` first verifies that the service on the port really is this program, **so it can't kill something else of yours.**

The default address is [http://127.0.0.1:18976](http://127.0.0.1:18976).

## Docker and servers

```powershell
Copy-Item .env.docker.example .env
docker compose up --build -d
```

Compose maps the port to the host loopback address only. Reach a remote server through an SSH tunnel:

```text
ssh -L 18976:127.0.0.1:18976 user@example.com
```

Full Docker, systemd, upgrade, and backup steps are in the [deployment guide](docs/部署指南.md). **Never expose a panel holding an API key directly to the internet.**

## Comparing multiple endpoints from the CLI

Create an **uncommitted** `*.local.txt` per endpoint containing three lines — HTTPS endpoint URL, API key, model name — then pass them explicitly:

```powershell
.\.venv\Scripts\python benchmark_token_speed.py `
  --configs endpoint-a.local.txt endpoint-b.local.txt `
  --mode daily-dialogue --samples 6 --warmups 1
```

The program **never searches for credential files on its own.** Results record only the config filename, model, and measurements — never the key or base URL.

## Worth noting technically

**Warm-ups are billed but not scored.** Warm-up requests really consume quota, so they're included in cost — but they never enter the formal speed distribution. Otherwise a single cold start drags the whole set down and you get a number nobody can reproduce. Those two facts have to be recorded separately.

**Complete usage and interrupted estimates are different fields.** A cleanly finished request uses the upstream's full `usage`; an interrupted one produces an estimate that is **explicitly labeled as an estimate.** Averaging both into one column is the classic mistake in this category of tool.

**WebSockets require same-origin *and* a local session token.** The token is generated by the launcher. Same-origin alone isn't enough — a local port is reachable by every user on a multi-user machine.

**Endpoint URLs are validated.** Remote upstreams must use HTTPS, and **endpoint URLs containing identity, query, or fragment data are rejected**, so credentials can't leak into logs via a URL.

**The pricing table states its own limits.** The bundled snapshot covers standard service tier with inputs up to 272K tokens, purely as a common conversion basis, and **does not represent your subscription bill.** Long-context, Batch, Flex, Priority, and regional processing are out of scope; the authority is [OpenAI's published pricing](https://developers.openai.com/api/docs/pricing).

**Tests and screenshots never hit a live model.** Automated tests, the demo, and project screenshots all avoid real model calls — so CI costs nothing and no screenshot contains a real response.

## Privacy and security

The API key and base URL exist only in the current browser session and the service process's memory. They are **never written to drafts, history, reports, or runtime logs**, and model output bodies are likewise kept out of previews, history, and reports.

The service binds to `127.0.0.1` by default.

> **This tool sends real API requests when you start a run, which may incur charges.** Read the [privacy note](PRIVACY.md) and [measurement method](docs/测量方法.md) first.

## What it doesn't do

- No concurrency leaderboards (that would make single-request speed meaningless).
- It doesn't proxy, cache, or rewrite your request content.
- It doesn't store API keys, base URLs, or model output bodies.
- It doesn't supply models, quota, or API service of any kind.
